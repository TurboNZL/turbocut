# TurboCut: project handoff

A lightweight, cross-platform multi-track video editor with built-in auto captions. Read `docs/ARCHITECTURE.md` first.

## Engine
Pinned to TurboNZL/turboengine (`.turboengine.json`; `docs/development/ENGINE.md` says what was taken from which module and what differs). The engine is a **reference, not a dependency**: before building something every app would want (updates, release naming, theme picker, settings layout, guides), look in the engine's `modules/` and `themes/docs/INTEGRATION.md` first. A cloud session sees only attached repositories: attach the engine read-only with `add_repo`. If you improve something here that other apps could use, add it to `docs/development/ENGINE_CONTRIBUTIONS.md` so it can be ported back. Read `PROJECT_BRIEF.md` for the long-lived goals and rules.

## Naming
- The product is styled **TurboCut** (capital T, capital C) in everything a person reads: UI, docs, window titles, error messages, comments, commit and PR text.
- Machine identifiers stay lowercase: repo and npm package `turbocut`, file-format tag `turbocut.captionPreset`, CSS/storage prefixes.

## User preferences
- Don't waste their usage. Fact-check and double-check yourself; use web search liberally.
- Reply in normal capitalised prose, not lowercase or slang, even when they write casually.
- Do not create a pull request by hand unless asked; `.github/workflows/auto-pr.yml` opens one for every pushed branch, and that is wanted. Commit trailers: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` and the `Claude-Session` line the harness provides.

## Decisions (don't re-ask)
- One TypeScript web app; Electron for Windows and Ubuntu, Capacitor for Android. No platform-specific app code.
- Themes come from `turbothemes`, installed from the engine (`git+https://github.com/TurboNZL/turboengine.git#path:/themes`; the old TurboNZL/turbothemes repository is retired), following its `docs/CONTRACT.md`.
- Shorts (9:16, under a minute) are the main case; 16:9 up to about 20 minutes must work. Low friction over detail.
- Time is integer frames. Core is pure and unit tested.
- Captions: presets are importable/exportable JSON; the bounce entrance must match the original `ass_bounce.py` (parity test in `test/captions.test.ts`).
- Transcription runs locally on WebGPU only (the remote GPU server option was removed on request; the `Transcriber` interface stays). Cancel must answer at once at every stage (`captionsPanel.ts` races the work against the abort).
- Twitch import: paste a clip URL in the Media tab; the landscape version (first asset) goes to the bin. The resolver is `src/twitch/clip.ts` (page) and `electron/twitch.cjs` (desktop, same logic); keep them in step. Not yet run against live Twitch (the sandbox cannot reach it).
- Versions are CalVer Year.Month.Update (`2026.10.3`), stamped by `build.yml`; the in-app updater reads GitHub Releases.
- **No GitHub Pages** (the owner does not want a paid hosting dependency) and no landing page site: the **home screen is in the app** (`src/app/home.ts`: start a project, updates, downloads with APK help, guides). `scripts/serve.mjs` is the self-host server (`--https` for LAN, since WebCodecs needs a secure page), shipped as `turbocut-<version>-web.zip`.
- Letter holes: **filled is the default** and means every hole is solid (not only holes narrower than the outline). Per-letter e2e with the real font in `e2e/run.mjs`; the metric must count enclosed pixels with alpha < 8 (a threshold of 200 counted the anti-aliased edge and hid the bug).
- Fonts: the font manager (`src/app/fontManager.ts`) is the one place to add, preview, default and remove fonts. Layouts: `src/app/layout.ts` (data and validation) and `layoutManager.ts` (Settings → Layout); the applied layout sets `data-panel` (`right`, `left`, `both`, `sheet`), `data-density`, `data-tools`, `--left-w`, `--right-w`, `--tl-h` on `#app`. Edit layouts in place (`Object.assign`), the controls hold a reference.
- Guides: user guides are `docs/guides/*.md`, bundled by `src/app/guides.ts`; the renderer (`markdown.ts`) only inserts text. Keep them accurate: they are what the owner reads on the phone.
- UI structure follows the engine: dialog title `h2` in a flex `.bt-titlebar`, panels `section.card.bt-panel` (`panel()` in `dom.ts`), in-page tabs `.tabs`/`.tab` with `role=tab` (never `.bt-tab`), SVG icons not emoji. e2e selects tabs with `getByRole('tab')`.
- Asset names are lowercase (`turbocut-2026.10.5-android.apk`).
- Caption styles: the built-in preset is generated from settings and read-only; user presets can bundle fonts (base64 `fonts` in the JSON, limits in `parsePresetFile`). Never commit font files (the e2e test font is generated by `make-media.sh`).

- Frame rate defaults to **60 fps** (`createProject`, `store.ts`); everything is integer frames of the project rate, so a default text layer is 180 frames. Imported 30 fps media simply repeats frames.
- Keyframes live **inline in the Clip tab** (`inspector.ts`): each setting is a `.prop-block[data-param]` with its own prev/next/key buttons and a `.kf-lane` of diamonds; the prev/next hotkeys follow the last touched setting (`activeParam`, `jumpKey(dir, only)`). There is no separate keyframe panel or Keys tab (`keysPanel.ts` is gone; a saved layout that lists Keys is migrated to Clip in `cleanLayout`). Redraw only a lane, never the panel, and e2e (`editing.mjs`) checks the panel's scrollTop and that no animation restarts.
- Panels/layouts: `layout.ts` (model: a layout is a list of named **divisions** `{name, side, tabs, size}`, left or right of the preview; four presets; old `panes` layouts are migrated in `cleanLayout`), `layoutStore.ts` (editing a preset makes a Custom copy), `panelHost.ts` + `splitter.ts` (a left and a right column of panes, resizable, double-click resets; on a phone one sheet under the timeline that never pushes the timeline out of view). The **dock is a setting** (`settings.dock`; `dock.ts` has three pages Home, Edit, Settings; Settings is a page above the dock, Home is `.home.docked`), not a layout; the window decorator switch lives in Settings → Look → Window. The first tab is `settings.openTab` (Media) and `settings.autoSwitch` turns off the jump to Clip or Captions on selection. Settings has a search box (focused when it opens) and grouped pages (`settingsDialog.ts`); the page redraws keep the scroll position (changing a hotkey must not jump to the top). Home is `home.ts` (`.home-*`): two snapping screens (starts, recent projects, open/import, the update line; then guides and downloads), the "show on startup" switch top right, no "Start editing" button.
- Tool bar: one `.edit-bar` element moved by `placeTools` (`main.ts`) to the play-bar row (`inline`: Trim start, Split, Trim end, ...), a row under it (`stage`, phones with "top"), under the timeline (`bottom`, centred) or floating bottom right (`float`, with a fold-away round button). Every tooltip shows the shortcut in force (`keyTip`).
- Drop-downs: `themedSelect.ts` upgrades every `select.input` (the native select stays, hidden, as the source of truth; e2e uses `pick()` from `e2e/browser.mjs`). Never use a native select popup. A field's text colour is set explicitly (`input.input { color: hsl(var(--fg)) }`): the browser's own default came out white on light.
- Recent projects (`recent.ts`, IndexedDB, keyed by project name), device sharing (`electron/share.cjs`, `share.ts`: UDP broadcast + HTTP on port 47903, consent per transfer; desktop only), preview sharpness and frame rate (`settings.previewScale`, `previewFps`; the sequential decoder takes a `stride`), drag-a-box selection on the timeline (`emptyPress`), the track menu is a right click at the pointer, selecting a caption never moves the playhead.
- Imports only fill the bin (`actions.importMedia(files, place=false, folder?)`); the bin has folders and per-kind drag grips (`binPanel.ts`); timeline selection is multi (`Store.toggleSelect/selectRange`), with right-click menus (`popupMenu`). Font boxes use `fontPicker.ts` (themed listbox), never a native `<select>`.
- Window: the desktop app is frameless and draws the engine's `.bt-wf*` title bar (`windowFrame.ts`, `electron/frameConfig.cjs`; on by default except macOS, Settings → Look → Window turns it off). Android updates inside the app through the `ApkUpdater` Capacitor plugin (`ApkUpdaterPlugin.java`, `updater.ts` `apkUpdater`); not compiled here, the first CI build is the check.
- Logo: the engine `logos` module (`branding/logo.json`, emblem `cut`, colour `#14c8d8`). Never hand-edit icon files: `CHROMIUM=<binary> PLAYWRIGHT_MODULE=node_modules/playwright-core/index.mjs node scripts/gen-icons.mjs --png`. Android's default Capacitor icon resources were deleted on purpose (the generator writes `drawable/ic_launcher_foreground.xml` and `values/colors.xml`).
- Desktop updates: `electron/updater.cjs` + `electron/debInstall.cjs` (the engine's `.deb` system: pkexec, then a sudo terminal, then `systemd-run --user` when `NoNewPrivs` is set; the app restarts only once `dpkg-query` shows the new version). The helpers are unit tested (`test/updater.test.ts`); the real install on a desktop has not been run.

- Selection: one thing at a time, a clip or a caption (`Store.select`, `selectCue`, `clearSelection`; Escape and a press on an empty track clear it). **Split** cuts the selected clip (with its linked partners), the selected caption (`core/captions.ts`), or with nothing selected only the active track; the CC row is a track (`CAPTION_TRACK`). It cuts every track only when no track was ever chosen.
- Timeline input: the plain wheel scrolls sideways, Ctrl/Alt + wheel zooms, Shift + wheel scrolls the tracks. The add-track button is the ruler's corner (`.tl-corner`).
- Captions: the accurate model is the default on a computer, balanced on a phone, and the first Generate on a device opens a chooser (`modelChoice.ts`, `transcribe.modelChosen`). Caption length (`transcribe.grouping`: auto = short lines for tall video, sentences for wide) and a sentence end always starts a new cue. Word timing quality is the model's: the code only clamps and cleans it.
- Text layers have their own entrance (pop in or none). Fonts: `src/app/systemFonts.ts` lists installed fonts (Electron: `queryLocalFonts()` works with no prompt, measured in Electron 44; browsers ask once; fallback is a well-known-names probe); `fontChoices()` is the one list for every font box. The file is the source of the engine's `modules/system-fonts`.
- Icons are inline SVG in `currentColor` (`src/app/icons.ts`), never emoji or symbol characters. The side panel carries `bt-shell` so Liquid Glass, Spotify and One UI float it; `styles.css` adds the gap they leave out on the right and bottom. The video preview has square corners in every look.
- **The "keyframe panel replays its opening animation" bug** was `.ks-fold[open] > .ks-body { animation }` plus a `<details>` rebuilt on every key change: an animation tied to `[open]` or to element insertion replays on every redraw. the panel has since been removed (keyframes are inline lanes), but the rule stands (`e2e/editing.mjs` 1b, with a negative control).
- Panels that show state must not be rebuilt for a change they already show (compare a signature; `showTab` does not re-insert the same panel): in looks that animate new elements it replays the animation.
- Engine pin is `c795082` (2026-10-17; includes `motion`, whose tk-* classes `motion.css` ports). `examples/verify-looks.mjs` from the engine passes on Settings and the editor (open the home screen's first start button first: `--open ".home-start"`).
- Projects are files: `.turbocut` JSON (`src/core/projectFile.ts`: `serializeProject`, `parseProject` that validates every clip, `matchMedia` by name then size). The file holds the edit, never the media: opening asks for the media again (`actions.relinkDialog`, also on drop). `store.dirty` drives the "Unsaved changes" dialog; File menu and Ctrl+S, Ctrl+O, Ctrl+N. `Asset.size` is optional so old projects still load. `pnpm e2e:project` saves, reopens in a fresh browser, relinks and exports.
- UI is deliberately calm (the other Turbo apps are): ghost icon buttons from `icons.ts` (SVG, never emoji), a File menu instead of loose buttons, labels only on wide screens, a flat side panel (no cards in cards; in the looks that float a side bar it floats, rounded, with `bt-shell`), the status line is a toast, keyframes are inline lanes. Every pressable thing shows a hand cursor (one rule in `styles.css`, `:disabled` shows not-allowed); a new kind of clickable element must be covered by it. Motion comes from `src/app/motion.css` (the engine's `tk-*` classes).
- e2e: suites that count frames pin 30 fps with `{ fps: 30 }` in `e2e/browser.mjs`; the rest use the 60 fps default.

## Commands
`pnpm install --ignore-scripts`, `pnpm test`, `pnpm typecheck`, `pnpm e2e:electron` (the built app in real Electron under xvfb), `pnpm e2e` (real export in headless Chromium, plus settings, bin, keys, editing, styles, fonts, layouts, home, guides and touch suites; `e2e/browser.mjs` starts every context with the home screen off, pass `{ home: true }` to test it; run `e2e/make-media.sh` once first; the sandbox Chromium cannot decode H.264).

- Fonts: never commit font files (Supercell's Squad Latin Black is proprietary; the user brings it). Users add fonts in the app; `.gitignore` blocks font extensions. Tests that need the real font read it from `e2e/.media/` (ignored).
- Caption outlines use `src/render/outlinedText.ts`: the outline only grows from the outside of the text, so counters (e, a, g) stay clear. A plain centred stroke fills them with outline colour; do not go back to that.
- Canvas `filter: blur()` ignores the canvas transform (measured). Convert project px to device px with the base transform. `pnpm e2e` has a preview-vs-export check with a tight threshold; keep it tight (a loose one passed the bug).
- Export: container follows the video codec (H.264 -> MP4 + AAC, else WebM + Opus). AAC falls back to `@mediabunny/aac-encoder` when the platform has none (Electron on Linux).
- When adding a test for a bug, run it against the broken code first (negative control).
- CI: `.github/workflows/ci.yml` (checks and e2e) and `build.yml` (APK + Windows + Linux + web: a pull request builds everything and keeps the files as artifacts; a push to main publishes a normal release `v<version>` with every file attached on its own, reusing the merged PR's files when the git tree and next version match, `scripts/ci/reuse-build.mjs`; **no pre-releases**; only the newest 5 are kept). The reuse path has never run on real GitHub: read the "Can a pull request build be published as it is?" step log first. Android uses a fixed public debug keystore (`android/debug.keystore`) so test APKs install over each other. The lockfile must not use the `github:` shorthand for turbothemes (it records an SSH address that CI cannot clone); the `git+https://` URL resolves to a codeload tarball.
- Touch UI (`src/app/timelineView.ts`): on touch the playhead is fixed in the middle and the timeline scrolls under it (panning = scrubbing). Only the SELECTED clip captures a finger (touch-action none, big handles); unselected clips use pan-x pan-y so they never block panning. `pnpm e2e:touch` drives this with raw CDP touch events. Chromium's `Input.synthesizeScrollGesture` and `synthesizePinchGesture` do not work here; use paced `Input.dispatchTouchEvent`. Pinch-to-zoom works (two fingers, zooms in place so the touched element survives).
- Captions from Whisper pass through `src/transcribe/post.ts` (clamp to the video, drop words on silence, collapse repeat loops). Default language is English (auto-detect on a multilingual model gave nonsense). The audio fed to the model is verified against ffmpeg by `pnpm e2e` (`speechAudio`). The model itself has never been run in the sandbox.
